# Product Inventory API

REST API built with Express.js to manage a product inventory: products, stock movements, warehouses, categories, suppliers, users and statistics.

Group 3 final project – BeTechified.

The `frontend/` folder contains the web app of the project, built with React.

> **Note:** data is stored in memory. Every restart of the server resets it to the sample data.

## Tech stack

- [Node.js](https://nodejs.org/) 20.19 or later (18 or later is enough for the API alone)
- [Express 5](https://expressjs.com/)
- [dotenv](https://github.com/motdotla/dotenv): loads environment variables from a `.env` file
- [nodemon](https://nodemon.io/): restarts the server on file changes (development only)
- Frontend: [React 19](https://react.dev/), [React Router 7](https://reactrouter.com/) and [Vite](https://vite.dev/)

## Getting started

```bash
git clone https://github.com/Ev-g127/Product-Inventory--API.git
cd Product-Inventory--API
npm install
```

Optional: create a `.env` file at the root of the project to choose the port (default: `3000`).

```
PORT=3000
```

Start the server:

| Command | What it does |
|---|---|
| `npm run dev` | Starts the server with nodemon, which restarts it on every file change (except in `frontend/`) |
| `npm start` | Starts the server with Node (use this in production) |

The API is then available at `http://localhost:3000`.

Every request is logged in the console with its date, method, URL, status and duration:

```
2026-11-25T21:20:04.512Z GET /products?lowStock=true 200 3ms
```

### Start the web app

Keep the API running, and in a second terminal:

```bash
cd frontend
npm install
npm run dev
```

The web app is then available at `http://localhost:5173`. It calls the API through Vite: `/api/stats` is sent to `http://localhost:3000/stats`. See [frontend/README.md](frontend/README.md).

## Data model

**Product**

| Field | Type | Notes |
|---|---|---|
| `id` | number | Generated by the API, never reused |
| `sku` | string | Unique (ignoring upper/lower case), used in the URLs, cannot be changed |
| `name` | string | |
| `price` | number | Greater than or equal to 0, with 2 decimals at most |
| `category` | string | Name of an existing category |
| `supplier` | string | Name of an existing supplier |
| `quantity` | number | Units in stock in all the warehouses, calculated by the API. `0` at creation, then only changed by stock movements |
| `lowStockThreshold` | number | Whole number, `5` by default. The stock is low when `quantity` is lower than or equal to it |
| `stock` | array | Units in each warehouse: `{ "warehouse", "quantity" }`. Only the warehouses that have some, calculated by the API |

**Stock movement**

| Field | Type | Notes |
|---|---|---|
| `id` | number | Generated by the API, never reused |
| `productId` | number | `id` of the product |
| `sku` | string | SKU of the product |
| `type` | string | `in` (units arrive), `out` (units leave) or `transfer` (units go from a warehouse to another) |
| `quantity` | number | Whole number greater than 0 |
| `reason` | string | For example `Delivery`, `Sale`, `Customer return` or `Damaged` |
| `from` | string | Name of the warehouse that the units leave. Only for `out` and `transfer` |
| `to` | string | Name of the warehouse where the units arrive. Only for `in` and `transfer` |
| `stockAfter` | number | Units in stock in all the warehouses after the movement, calculated by the API |
| `date` | string | Date and time of the movement (ISO 8601), set by the API |

**Warehouse**

**Supplier**

|---|---|---|
| `id` | number | Generated by the API, never reused |

**User**

| Field | Type | Notes |
|---|---|---|
| `id` | number | Generated by the API, never reused, used in the URLs |

| `Product 3` | 0 | 0 | 0 | 0 |
| `Product 4` | 0 | 30 | 20 | 50 |

## Endpoints

- Request bodies are JSON: send the header `Content-Type: application/json`.
- SKUs and names in the path of a URL are case-sensitive: `/categories/Food` and `/categories/food` are different.
- Texts in a URL must be URL-encoded: `Category 1` becomes `Category%201`.

### Products

| Method | Path | Description | Success |
|---|---|---|---|
| `GET` | `/products` | List all products, or filter and sort them with query parameters (see the table below) | `200` |
| `GET` | `/products/:sku` | Get one product | `200` |
| `POST` | `/products` | Create a product. Body: `sku`, `name`, `price`, `category`, `supplier` (required) and `lowStockThreshold` (optional) | `201` |
| `PATCH` | `/products/:sku` | Update a product. Body: any of `name`, `price`, `category`, `supplier`, `lowStockThreshold`. Fields not sent are left unchanged | `200` |
| `DELETE` | `/products/:sku` | Delete a product | `200` |

Query parameters of `GET /products`:

| Parameter | What it does | Example |
|---|---|---|
| `name` | Keeps the products whose name contains the text | `?name=phone` |
| `category` | Keeps the products of the category | `?category=Category%201` |
| `supplier` | Keeps the products of the supplier | `?supplier=Supplier%201` |
| `minPrice`, `maxPrice` | Keep the products whose price is between these values (included) | `?minPrice=5&maxPrice=20` |
| `lowStock` | `true` keeps the products whose stock is low, `false` keeps the others | `?lowStock=true` |
| `sort` | Sorts by `name`, `price` or `quantity` | `?sort=price` |
| `order` | `asc` (default) or `desc`. Only with `sort` | `?sort=price&order=desc` |

Several parameters can be used together: a product must match all the filters. Upper and lower case do not matter in `name`, `category` and `supplier`.

### Stock movements

| Method | Path | Description | Success |
|---|---|---|---|
| `GET` | `/products/:sku/movements` | List the stock movements of a product, from the oldest to the newest | `200` |
| `POST` | `/products/:sku/movements` | Move units of a product. Body: `type`, `quantity`, `reason` (required), `from` and/or `to` (see the table below) | `201` |

| `type` | What happens | Warehouses to send |
|---|---|---|
| `in` | Units arrive: delivery, customer return... | `to` |
| `out` | Units leave: sale, loss, damage... | `from` |
| `transfer` | Units go from a warehouse to another | `from` and `to` |

### Warehouses

| Method | Path | Description | Success |
|---|---|---|---|
| `GET` | `/warehouses` | List all warehouses | `200` |
| `GET` | `/warehouses?name=text` | List the warehouses whose name contains `text` (case-insensitive) | `200` |
| `GET` | `/warehouses/:name` | Get one warehouse | `200` |
| `GET` | `/warehouses/:name/products` | List the products of a warehouse: `sku`, `name` and `quantity` in this warehouse | `200` |
| `GET` | `/warehouses/:name/movements` | List the stock movements from or to a warehouse, from the oldest to the newest | `200` |
| `POST` | `/warehouses` | Create a warehouse. Body: `name`, `address` (all required) | `201` |
| `PATCH` | `/warehouses/:name` | Update a warehouse. Body: `newName` and/or `address`. Fields not sent are left unchanged | `200` |
| `DELETE` | `/warehouses/:name` | Delete a warehouse | `200` |

### Statistics

| Method | Path | Description | Success |
|---|---|---|---|
| `GET` | `/stats` | Get a summary of the inventory | `200` |

| Field | Meaning |
|---|---|
| `totalProducts` | Number of products |
| `totalUnits` | Units in stock, all the products together |
| `stockValue` | Value of the stock: `price` × `quantity`, added up for all the products |
| `lowStock` | SKUs of the products whose stock is low |
| `byCategory` | Number of products and units in each category |
| `byWarehouse` | Number of products and units in each warehouse |

### Business rules

- A product's `category` and `supplier` must already exist, and so must the warehouses of a stock movement.
- SKUs, category names, supplier names, warehouse names and user emails must be unique, ignoring upper/lower case (`Food` and `food` are the same name).
- Spaces at the start and end of SKUs, of movement reasons, of user emails and of product, category, supplier, warehouse and user names are removed (`" Food "` is saved as `Food`).
- The SKU of a product never changes: `PATCH /products/:sku` rejects `sku`.
- The stock of a product only changes through stock movements: `POST /products` and `PATCH /products/:sku` reject `quantity` and `stock`.
- A stock movement cannot take more units from a warehouse than the product has there, even if the other warehouses have some.
- A transfer needs two different warehouses. It does not change the total quantity of the product.
- Stock movements cannot be changed or deleted. To correct a mistake, create the opposite movement.
- A new product that uses the SKU of a deleted product starts with an empty stock and an empty history.
- Renaming a category, a supplier or a warehouse also updates the products that use it. For a warehouse, the history is updated too.
- A category or a supplier cannot be deleted while products still use it.
- A warehouse cannot be deleted while it contains products, or if stock movements have used it.
- Users have no password, because the API has no login. Their role does not limit what they can do.

## Examples

**Create a product**

```http
POST /products
Content-Type: application/json

{ "sku": "SKU-100", "name": "Wireless Mouse", "price": 19.99, "category": "Category 1", "supplier": "Supplier 1" }
```

Response `201 Created`:

```json
{ "id": 5, "sku": "SKU-100", "name": "Wireless Mouse", "price": 19.99, "category": "Category 1", "supplier": "Supplier 1", "quantity": 0, "lowStockThreshold": 5, "stock": [] }
```

**Update only the price of a product**

```http
PATCH /products/Product%201
Content-Type: application/json

{ "price": 12.5 }
```

Response `200 OK`:

```json
{ "id": 1, "sku": "Product 1", "name": "Product One", "price": 12.5, "category": "Category 1", "supplier": "Supplier 1", "quantity": 20, "lowStockThreshold": 5, "stock": [{ "warehouse": "Warehouse 1", "quantity": 15 }, { "warehouse": "Warehouse 2", "quantity": 5 }] }
```

**Add units of a product to a warehouse**

```http
POST /products/Product%201/movements
Content-Type: application/json

{ "type": "in", "quantity": 10, "reason": "Delivery", "to": "Warehouse 1" }
```

Response `201 Created`:

```json
{ "id": 1, "productId": 1, "sku": "Product 1", "type": "in", "quantity": 10, "reason": "Delivery", "to": "Warehouse 1", "stockAfter": 30, "date": "2026-11-25T15:21:52.223Z" }
```

**Transfer units of a product between two warehouses**

```http
POST /products/Product%201/movements
Content-Type: application/json

{ "type": "transfer", "quantity": 6, "reason": "Restock", "from": "Warehouse 1", "to": "Warehouse 3" }
```

Response `201 Created`:

```json
{ "id": 1, "productId": 1, "sku": "Product 1", "type": "transfer", "quantity": 6, "reason": "Restock", "from": "Warehouse 1", "to": "Warehouse 3", "stockAfter": 20, "date": "2026-11-25T15:21:52.223Z" }
```

**Take more units than the warehouse has**

```http
POST /products/Product%201/movements
Content-Type: application/json

{ "type": "out", "quantity": 10, "reason": "Sale", "from": "Warehouse 2" }
```

Response `409 Conflict`:

```json
{ "error": "Not enough stock in Warehouse 2: only 5 available" }
```

**List the products of a warehouse**

```http
GET /warehouses/Warehouse%202/products
```

Response `200 OK`:

```json
[{ "sku": "Product 1", "name": "Product One", "quantity": 5 }, { "sku": "Product 4", "name": "Product Four", "quantity": 30 }]
```

**Search products by name**

```http
GET /products?name=two
```

Response `200 OK`:

```json
[{ "id": 2, "sku": "Product 2", "name": "Product Two", "price": 15.99, "category": "Category 2", "supplier": "Supplier 2", "quantity": 5, "lowStockThreshold": 5, "stock": [{ "warehouse": "Warehouse 1", "quantity": 5 }] }]
```

**Filter and sort the products**

```http
GET /products?lowStock=true&sort=price&order=desc
```

Response `200 OK`:

```json
[{ "id": 3, "sku": "Product 3", "name": "Product Three", "price": 20.99, "category": "Category 3", "supplier": "Supplier 3", "quantity": 0, "lowStockThreshold": 5, "stock": [] }, { "id": 2, "sku": "Product 2", "name": "Product Two", "price": 15.99, "category": "Category 2", "supplier": "Supplier 2", "quantity": 5, "lowStockThreshold": 5, "stock": [{ "warehouse": "Warehouse 1", "quantity": 5 }] }]
```

## Errors

Every error is returned as JSON:

```json
{ "error": "Product not found" }
```

| Status | When |
|---|---|
| `400 Bad Request` | Missing field, wrong type, empty text, invalid email or role, invalid price, quantity, low stock threshold or movement type, invalid filter or sort, nothing to update, `quantity` or `stock` sent to `POST /products` or `PATCH /products/:sku`, `sku` sent to `PATCH /products/:sku`, missing or unexpected warehouse in a movement, unknown category, supplier or warehouse in the body, malformed JSON, badly encoded URL |
| `404 Not Found` | The product, category, supplier, warehouse, user or route does not exist |
| `409 Conflict` | The SKU, name or email is already used, there is not enough stock in the warehouse, or a deletion is blocked because products or stock movements still use the category, supplier or warehouse |
| `500 Internal Server Error` | Unexpected server error (details are only written in the server logs) |

## Postman

The `postman/` folder contains two collections. In Postman, click **Import** and select both files.

| File | Content |
|---|---|
| `product-inventory.postman_collection.json` | Every route with its error cases: 91 requests and 271 tests |
| `product-inventory-demo.postman_collection.json` | The 13 requests of the demo, in order. The scenario is in `DEMO.md` |

- Start the server before you send the requests. The address of the API is in the collection variable `baseUrl` (default: `http://localhost:3000`).
- To run all the tests, open the menu of the first collection and choose **Run**. It deletes what it creates, so it can be run several times.
- Restart the server before the demo: it expects the sample data.
